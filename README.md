## Различия между in-memory и файловой реализацией

| Свойство                  | `MemoryDatabase`           | `FileDatabase`                          |
|---------------------------|----------------------------|-----------------------------------------|
| Где хранятся данные       | в памяти процесса          | в JSON-файле на диске                   |
| После завершения работы   | данные теряются            | данные сохраняются и загружаются снова  |
| Сохранение                | не требуется               | после каждого добавления записи         |
| Источники ошибок          | некорректные данные        | то же, плюс ошибки файла (`DatabaseError`) |

Обе реализации проходят один и тот же набор тестов (`tests/contract.py`).

## Формат файла

```json
{
  "table": "students",
  "columns": ["student_id", "first_name", "second_name", "age", "sex"],
  "records": [
    [1, "Иван", "Иванов", 20, "M"]
  ]
}
```

При загрузке файл проверяется: корректный JSON, ожидаемая структура таблицы,
допустимые значения полей, уникальность `id`. Иначе выбрасывается `DatabaseError`,
а программа сообщает об ошибке и завершается. Запись выполняется через временный
файл, поэтому сбой при сохранении не портит существующие данные. Если сохранить
запись не удалось, она не остаётся и в памяти.

## Обработка ошибок

- некорректные данные пользователя → сообщение `Ошибка: ...`, программа продолжает работу;
- нечисловой ввод в числовых полях → повторный запрос;
- повреждённый или недоступный файл → `DatabaseError`;
- прерывание ввода (Ctrl+C, Ctrl+D) → аккуратный выход.

## Запуск

Требуется Python 3.10 или новее. Из корня репозитория:

```
python -m src.db                      # in-memory (данные не сохраняются)
python -m src.db --storage file       # файл data/students.json
python -m src.db --storage file --path my_students.json
```

Проверка сохранения данных: запустите с `--storage file`, добавьте запись,
выйдите (`0`), запустите снова с теми же параметрами и выберите «Показать все
записи» — запись должна быть на месте.
